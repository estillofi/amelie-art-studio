# Добавление тем и слов

Через чат можно подготовить набор под интерес ребёнка, сверить переводы и примеры, затем загрузить JSON из раздела взрослого → «Добавить набор тем». Для изменения работающего приложения нужен доступ к его конкретному серверу или загрузка файла взрослым: сам чат не получает доступ к Railway автоматически.

Пример запроса: «Подготовь для Амели тему про рисование: 4 простых слова, короткая фраза для каждого, перевод и подходящую иллюстрацию. Уровень — английский с нуля. Сначала покажи набор». Перед добавлением стоит сверить слова с учебником и уже изученным материалом.

Для Амели приоритет — [вводный маршрут через рисование и айкидо](learning-plan.md): до двух новых единиц за короткое занятие, сначала понимание на слух. Spotlight используется как школьный ориентир; порядок и сложность новых наборов не привязываются к его страницам.

Формат — объект с массивами `topics` и `words`. Готовый небольшой пример: [content-example.json](content-example.json). Пример не добавляется автоматически при запуске.

- У темы: `id`, `en`, `ru`, `icon`, `color` (шесть hex-цифр с `#`), `order`.
- У слова: `id`, `topic` (id темы), `en`, `ru`, `order`; необязательные `pic`, `ex`, `exRu`, `color` или `num`.
- Идентификаторы — латинские буквы, цифры, дефисы и подчёркивания, до 100 символов. Они должны быть стабильными: прогресс привязан к id слова.
- Одинаковый id обновляет запись, новый id добавляет. Импорт не удаляет темы, слова, прогресс или рисунки. Все изменения набора применяются вместе, либо не применяются вовсе.
- Массив `topics` может быть пустым, если слова относятся к уже существующим темам. Новую тему добавляйте вместе со словами. Эмодзи и примеры — текст, HTML не поддерживается.

На сервере или локально тот же импорт можно выполнить командой, указав `DATA_DIR` нужной базы:

```sh
npm run content -- docs/content-example.json --profile amelie --dry-run
npm run content -- docs/content-example.json --profile amelie
```

`--dry-run` проверяет весь набор, включая ссылки на темы, и откатывает изменения. Повторный обычный импорт обновляет записи с теми же id без дубликатов. Сначала сделайте резервную копию рабочей базы.

Отдельные слова по-прежнему добавляются формой в разделе взрослого. На GitHub Pages новые серверные наборы недоступны: контент там обновляют файлами `data/topics.json` и `data/words.json` через GitHub.

При будущей генерации через API ключ должен оставаться на сервере. Генератор сначала создаёт черновик: взрослый проверяет язык, сложность и иллюстрации, затем публикует набор через этот же механизм импорта. В этом выпуске платных API-вызовов и автоматической генерации нет.

В семейной конфигурации CLI требует `--profile`: он изменяет именно `profiles/amelie.sqlite`, `demo.sqlite` или `sandbox.sqlite`. Команда без профиля завершается ошибкой, а не записывает набор в старую неиспользуемую общую базу. В локальном режиме без семейных аккаунтов параметр можно не указывать. Список файлов `data/*.json` используется только при первичном создании базы; добавление слова в Git и деплой сами по себе не меняют уже существующий словарь семьи.

Полный современный экспорт прогресса включает также темы и все слова набора. Старые файлы с одними собственными словами принимаются как раньше. При обновлении формулировки сохраняйте id; новый id означает другую карточку с новым расписанием. Импорт контента не удаляет слова, интервалы, звёзды, задания или рисунки.
