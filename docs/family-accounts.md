# Семейные входы и первичный перенос

Выпуск `2026.10.21-family-1` создаёт четыре входа. Это одна семья, без регистрации других семей и оплаты внутри приложения.

| Логин | Права и данные |
| --- | --- |
| `parent` | Выбор альбома Амели, Демо или Песочницы; задания, настройки, контент, импорт и экспорт, выдача паролей |
| `amelie` | Занятия, звёзды и рисунки только Амели |
| `demo` | Отдельный чистый альбом «Демо» |
| `sandbox` | Отдельный чистый альбом «Песочница» |

При первом запуске пароль `parent` берётся из существующего `APP_PASSWORD`. Дальше сохраняется его scrypt-хеш. Перезапуск не сбрасывает пароли и прогресс. `APP_USER` оставлен для совместимости конфигурации размещения; логин родителя теперь `parent`.

В разделе взрослого выберите «Входы и пароли для детей» → «Выдать пароль». Новый пароль показан только в ответ на это действие: сохраните его и передайте семье вне публичного репозитория. «Новый пароль» отзывает прежний пароль и все открытые сессии этого детского входа. При создании аккаунтов детские входы заблокированы до выдачи первого пароля.

Данные находятся на постоянном диске: `accounts.sqlite` содержит хеши паролей и токенов сессий, `profiles/amelie.sqlite`, `profiles/demo.sqlite`, `profiles/sandbox.sqlite` содержат независимые словари, задания и результаты. Внутренний id записи личной статистики остаётся `amelie` в каждой базе ради совместимости старого формата экспорта. Выбор базы задаёт серверная сессия; переданный клиентом id не переключает альбом.

Сессия хранится в HttpOnly/SameSite=Strict cookie, на HTTPS также Secure. Родительская сессия действует 12 часов, детская — 30 дней. API проверяет роль и выбранный альбом. Браузер хранит кэш и очередь отдельно для каждой пары «аккаунт + альбом». Смена профиля и выход сначала требуют подтверждения всех сохранений; запрос из устаревшей вкладки с другим альбомом отклоняется. Старый серверный тестовый кэш автоматически не переносится. Полноценная одновременная работа нескольких устройств с одним альбомом пока не поддерживается.

## Перенос настоящего прогресса

Обычный перенос: войдите как `parent`, выберите Амели, загрузите JSON в разделе резервной копии. Сервер проверит весь файл без изменений, покажет число звёзд, наклеек, рисунков и карточек. После подтверждения сохранит SQLite-копию в `backups/` и заменит личные результаты одной транзакцией. Демо-альбомы не меняются. Старый экспорт без `assignments` поддерживается. Звёзды разных источников не складываются.

Для первого управляемого переноса доступна команда, читающая файл из закрытого каталога:

```sh
node scripts/import-child-progress.js /secure/amelie-progress.json
node scripts/import-child-progress.js /secure/amelie-progress.json --apply
```

Нужны `APP_PASSWORD` и тот же `DATA_DIR`, что использует приложение. Первая команда только проверяет файл; вторая создаёт резервную копию и импортирует в пустой альбом Амели. SHA-256 исходного файла записывается в транзакции с результатами: повторный запуск с тем же файлом пропускает импорт и сохраняет новые занятия. Другой файл или уже занятый альбом блокируют первичный перенос. Ручной последующий импорт остаётся доступен только родителю с явным подтверждением.

При автоматизированном размещении можно временно положить файл по приватному пути, указанному в `AMELIE_IMPORT_FILE`, либо в `scripts/initial-progress.private.json` закрытого артефакта деплоя. Сервер выполнит такой же первичный перенос перед открытием порта. Исходный файл и его персональные сведения не должны попадать в Git или публичные ресурсы. После успешной проверки удалите файл из следующего артефакта; запись о выполнении остаётся на постоянном диске.

Полная семейная резервная копия: `npm run backup -- --family /safe/backups/family-YYYY-MM-DD`. Укажите серверный `DATA_DIR`, сохраните каталог вне постоянного диска. Для восстановления остановите сервис, отдельно сохраните текущие базы вместе с WAL/SHM, восстановите `accounts.sqlite` и `profiles/*.sqlite` из копии без устаревших WAL/SHM и запустите сервис.

При первом переходе с общей базы сервер сохраняет `before-family-*.sqlite`. Старая `amelie.sqlite` остаётся архивом тестового профиля и не копируется в детские альбомы. Для отката сохраните весь постоянный диск, включая новые базы и WAL-файлы; не удаляйте новые результаты при откате кода.
