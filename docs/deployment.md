# Размещение для одной семьи

VPS — арендованный удалённый сервер, а Docker — способ запустить приложение в контейнере на нём. Собственный компьютер не обязан работать постоянно. Railway запускает контейнер за вас, предоставляет адрес и HTTPS и требует меньше администрирования. Для первого семейного пилота достаточно Railway с одним сервисом и одним постоянным диском.

## Railway

1. Загрузите проверенную версию в GitHub и создайте в Railway сервис из этого репозитория. Файлы `Dockerfile` и `railway.json` уже подготовлены. GitHub Pages останется отдельным статическим прототипом.
2. Добавьте к сервису **Volume**, смонтированный в `/data`. База должна находиться именно на постоянном диске: файловая система контейнера пересоздаётся при деплое. Используйте одну реплику сервиса; SQLite в этом выпуске не предназначен для нескольких независимо работающих экземпляров.
3. В Railway Variables задайте `APP_USER` и длинный уникальный `APP_PASSWORD`. Значения вводите в настройках Railway, не в чат и не в Git. Контейнер уже задаёт `HOST=0.0.0.0` и `DATA_DIR=/data`. Railway может передать собственный `PORT`, приложение его использует.
4. Выполните Deploy и создайте публичный домен Railway с HTTPS. Откроется форма входа. Логин родителя — `parent`, первый пароль — существующий `APP_PASSWORD`. Взрослый выдаёт разные детские пароли в разделе «Входы и пароли для детей». Настройки и импорт проверяются сервером. При первом обновлении старая общая база сохраняется отдельной резервной копией; новые детские альбомы создаются пустыми до переноса.
5. Проверьте главную, озвучку, прохождение карточки и рисунок. В разделе взрослого дождитесь сообщения «Все результаты сохранены на сервере». Перезапустите сервис и убедитесь, что результаты остались. В новом браузере с тем же детским аккаунтом должен отображаться тот же прогресс.

Семейный пилот размещён на https://amelie-art-studio-production.up.railway.app. Код находится в ветке `feature/server-pilot`; `main` и GitHub Pages остаются отдельным прототипом. Railway подключён напрямую к репозиторию `estillofi/amelie-art-studio` и ветке `feature/server-pilot`: push в эту ветку запускает сборку и деплой сервиса. Перед публикацией выполняйте проверки для изменённого поведения. Постоянный диск `/data` сохраняется при обновлении. GitHub Pages из `main` остаётся отдельным статическим прототипом.

Версия выпуска видна внизу раздела для взрослых и в `GET /api/health` (поле `version`). Для проверки фактического деплоя сравнивайте ещё и файлы работающего сервиса с опубликованной веткой; статус Success подтверждает запуск, но сам по себе не доказывает наличие нужного изменения интерфейса. Стоимость сервиса и диска зависит от тарифа Railway.

Изменения с другого устройства видны после перезагрузки страницы. В актуальной версии ответы и награды записываются отдельными действиями: два устройства не перезаписывают абсолютный счёт звёзд, повтор запроса не начисляет награду второй раз. На обоих устройствах нужно открыть актуальную версию. Ответы одного дня не продвигают карточку сразу через несколько уровней. Поздно пришедший старый ответ сохраняется в истории, но не заменяет более новое расписание.

## Перенос из GitHub Pages

На устройстве и в том браузере, где Амели занималась:

1. Откройте старое приложение → «Для родителей» → «Скачать прогресс». Сохраните исходный JSON отдельно.
2. Откройте новый адрес → войдите как `parent` → «Для родителей» → выберите альбом «Амели» → «Загрузить». Проверьте показанные количества и подтвердите замену. Сервер автоматически делает копию выбранной базы перед импортом. Импорт выполняется одной транзакцией: некорректный файл не должен частично перезаписать результаты.
3. Проверьте звёзды, слова и галерею. Импорт заменяет прогресс, поэтому сначала скачайте копию текущих результатов нового сервера, если на нём уже занимались.

Новый домен не видит `localStorage` GitHub Pages: перенести его автоматически невозможно. Если статический прототип заменили сервером по тому же адресу, раздел взрослого предложит перенести обнаруженный старый прогресс с устройства. Прежняя копия сохраняется до успешного переноса.

## Резервные копии и восстановление

Кнопка «Скачать прогресс» после подтверждения очереди получает полный снимок выбранного альбома с сервера: результаты, все темы и слова, задания, рисунки и квитанции действий для защиты от повторной отправки. Старые экспорты без новых полей по-прежнему принимаются. Новые снимки нужно восстанавливать актуальной версией приложения. Импорт JSON ограничен 32 МиБ и проверяется до замены данных. Пароли и сессии не входят в файл прогресса. Полная копия SQLite включает также серверные данные:

```sh
npm run backup -- /safe/backups/amelie-2026-10-20.sqlite
```

Команда использует SQLite backup API и работает при запущенном приложении. Она не перезаписывает существующий файл. Укажите тот же `DATA_DIR`, что использует сервер. Эта команда архивирует прежнюю общую базу; для всех новых семейных баз выполните `npm run backup -- --family /safe/backups/family-YYYY-MM-DD`. Команда через SQLite backup API сохраняет `accounts.sqlite` и три базы `profiles/` в новый закрытый каталог. Копии перед импортами автоматически находятся в `/data/backups/`. Порядок первичного переноса описан в [семейных аккаунтах](family-accounts.md). На Railway её можно выполнить в контейнере из терминала сервиса, например `node scripts/backup.js /data/backups/amelie-2026-10-20.sqlite`; затем скачайте копию и храните вне этого диска. Копия на том же диске не защищает от потери диска.

Чтобы восстановить полную базу, остановите сервис, сохраните текущую базу вместе с её WAL/SHM-файлами, замените остановленную базу файлом резервной копии под именем `amelie.sqlite`, уберите из рабочего каталога старые WAL/SHM-файлы и запустите сервис. Проверьте результаты. Не копируйте только основной файл работающей базы обычной командой `cp`: последние записи могут находиться в WAL.

## VPS с Docker

На VPS с установленным Docker соберите этот репозиторий и создайте постоянный диск:

```sh
docker build -t amelie-art-studio .
docker volume create amelie-data
docker run -d --name amelie --restart unless-stopped \
  --env-file /secure/path/amelie.env \
  -p 127.0.0.1:3000:3000 \
  --mount source=amelie-data,target=/data \
  amelie-art-studio
```

Файл `amelie.env` должен содержать только ваши `APP_USER` и `APP_PASSWORD`, с доступом только владельцу. Перед контейнером настройте Caddy или Nginx с HTTPS и доменом. Порт приложения привязан к loopback VPS, наружу выходит HTTPS прокси. Для входа с паролем используйте только HTTPS. При обновлении пересобирайте контейнер, сохраняя том `amelie-data` и делая предварительную резервную копию.

Это первая версия для одной семьи. Аккаунты разных семей и биллинг потребуют отдельного этапа до монетизации.

## Автоматические дневные копии

Сервер при запуске и затем каждый час проверяет наличие сегодняшней копии. Если её нет, SQLite backup API сохраняет `accounts.sqlite` и три базы `profiles/` в приватный временный каталог. Каждая база проходит `PRAGMA integrity_check`, в manifest записывается SHA-256, затем готовый каталог публикуется атомарным переименованием. За день получается одна копия. Хранятся последние 14 каталогов `/data/backups/auto-YYYY-MM-DD`; пользовательские копии перед импортом не удаляются этой ротацией. Дата последней успешной копии видна родителю.

Это копии на том же постоянном диске: они помогают при ошибочном импорте и обновлении, но не заменяют копию вне диска. Внешнее хранилище и расписание выгрузки пока не подключены. До их настройки регулярно скачивайте полный JSON и сохраняйте его отдельно. Для восстановления паролей нужна полная семейная SQLite-копия, не только JSON выбранного ребёнка.

Восстановление семейной копии: сначала проверьте её в отдельном каталоге, откройте все базы и проверьте контрольные суммы/целостность и результаты. Для рабочего восстановления остановите сервис, сохраните текущий каталог `/data` отдельно, верните `accounts.sqlite` и нужные `profiles/*.sqlite` из согласованной копии; не оставляйте рядом старые WAL/SHM этой базы. Затем запустите сервис и проверьте входы и данные. Не заменяйте работающие файлы и не удаляйте постоянный диск при обычном деплое.
